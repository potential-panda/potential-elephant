# Business Assessment: Potential Elephant

Date: 2026-06-10

## Executive Assessment

Potential Elephant is useful for top-of-funnel discovery, but it is not yet strong enough for the core business purpose: finding thematic laggards that deserve research before re-rating.

It is already collecting valuable signal. As of 2026-06-10, the local API/data store showed roughly:

- 343k Yahoo Finance Japan BBS comments
- 2,112 Yahoo BBS evaluation snapshots
- 1,290 Minkabu records
- Recent news headlines
- TDnet disclosures
- Daily price records
- A running scheduler

That means the project has a real data foundation. The main business gap is not data collection; it is candidate qualification.

The system should prioritize:

```text
value_chain fit + laggard status + catalyst evidence + sentiment confirmation
```

Today, the digest often prioritizes:

```text
BBS heat + analyst target + vague theme language
```

This is helpful for finding smoke, but not yet disciplined enough to decide whether the smoke is from a real thematic fire or just crowd noise.

## Where The System Helps

The tool already does several useful things:

- It finds crowd heat quickly. BBS rank and comment speed catch active names such as `3350.T`, `5016.T`, `8136.T`, and `6981.T`.
- It uses the right kinds of sources: BBS sentiment, comments, Minkabu consensus, TDnet, news, price context, and a curated atlas.
- Deep dives can reject noise. The `3350.T` deep dive correctly concluded "Pass for now" because Metaplanet is mostly a Bitcoin/speculation story, not a clean fit for the current four value_chains.
- The atlas provides a promising structure for comparing companies by theme and supply-chain stage.

## Where The System Falls Short

The daily product still confuses attention with business relevance.

The tool is designed around a strong investment philosophy: find confirmed thematic waves, map the supply chain, then look for structurally relevant companies that have not yet been re-rated by the market. The current digest does not enforce that philosophy strongly enough.

Main issues:

- It does not yet use the atlas as a quantitative map of relative laggards.
- It sometimes promotes tickers with high BBS activity before proving value_chain fit.
- It relies too much on the LLM to judge candidates instead of first creating a deterministic score/ranking.
- It does not consistently explain why a ticker appeared in a reproducible way.
- It does not remember prior "pass" decisions strongly enough.

## Evidence From Data

### 3350.T: Useful Heat Detection, But Poor Value Chain Fit

The 2026-06-09 digest surfaced `3350.T` as `[NEW NAME]`. The signal was understandable: price had fallen sharply, comment speed had accelerated, and Minkabu showed bullish analyst context.

But from a business-purpose perspective, this is not a strong value_chain candidate. Metaplanet is mostly a Bitcoin/speculation story, not a clean fit for `ai_infra`, `tech_local`, `physical_ai`, or `longevity`.

The deep dive correctly identified this and concluded `Pass for now`. That means the system can reject noise after a user spends time on a deep dive, but the digest should ideally classify it as "crowd heat/noise" before it consumes attention.

### 5016.T: Potential False Negative

`5016.T` is more interesting. The digest flagged it as a holding signal, and Minkabu identifies JX Advanced Metals as a nonferrous metals and electronic materials company with semiconductor, rare metal, optical-device, and advanced-material themes.

That sounds plausibly relevant to `tech_local` or `ai_infra` bottleneck-stage materials.

However, the existing deep dive said it had no clear value_chain fit and treated it as mostly noise. That may be a false negative. It suggests the system is not yet good enough at mapping materials/specialty suppliers into the value_chain framework.

### 8136.T: Crowd Panic, Not Thematic Signal

`8136.T` had a major comment-speed spike, around `88.26 c/h`, but the live BBS sentiment was strongly negative. This is useful as a "crowd panic" alert, but not necessarily useful for the current thematic supply-chain strategy unless a separate IP/consumer value_chain is intentionally added.

This kind of name should be categorized separately from value_chain candidates.

## Business Verdict

Current usefulness:

- Discovery engine: useful, about 7/10
- Thematic laggard scout: promising but currently about 4/10
- Research assistant after a ticker is chosen: useful, about 6/10
- Decision support for "what deserves my time today?": not reliable enough yet

The tool has the right raw ingredients. The highest-value next step is to become stricter about candidate qualification before the digest is written.

## Recommended Improvements

### 1. Add A Deterministic Candidate Score

For every ticker, compute a pre-LLM score:

```text
value_chain_fit_score
relative_laggard_score
bbs_heat_score
sentiment_quality_score
catalyst_score
noise_penalty
```

Only let the LLM write the final explanation after this ranking exists.

### 2. Split The Digest Into Three Queues

Do not mix different signal types in one undifferentiated digest.

Recommended queues:

```text
A. Value Chain Candidates
   Fits a value_chain, underperformed peers, has plausible catalyst.

B. Holding Signals
   Already in atlas/watchlist, price down but thesis/sentiment intact.

C. Crowd Heat / Noise
   High BBS activity, but no value_chain fit yet.
```

`3350.T` belongs in C unless a crypto value_chain is intentionally added. `5016.T` may belong in A. `8136.T` belongs in C.

### 3. Make Relative Laggard Detection The Core Screen

The stored price data already enables this. For each value_chain/stage, compute stage median returns and show names that underperform comparable companies.

Example output:

```text
5016.T
Stage candidate: tech_local / bottleneck
2w return: -11.6%
Stage median: +x%
BBS: bull 62.5%, speed stable
Minkabu: analyst buy, semiconductor/electronic material themes
Risk: recent IPO / valuation / sentiment weakening
Next action: read TDnet + latest company filing
```

### 4. Add Freshness And Reproducibility To Every Hint

Each digest hint should show:

- BBS snapshot time
- Latest comment time
- Latest price date
- Latest Minkabu scrape time
- Source links

The digest should make it possible to answer: "Why did this appear today?"

### 5. Normalize Data Quality Before Trusting Sentiment

Some Yahoo evaluation rows appear to have schema drift where bearish fields are missing or become `NaN`. This can make bull/bear interpretation wrong.

All evaluation records should be normalized to the same five sentiment fields:

```text
strongest
strong
both
weak
weakest
```

Missing values should be coerced to zero or explicitly marked as unavailable.

### 6. Fix Market Routing

Scheduler logs showed attempts such as `STM.T`, `XLU.T`, and `LLY.T` against Yahoo Japan style URLs. That wastes scrape time and may introduce bad data assumptions.

US tickers should use US-compatible sources, or be excluded from Yahoo JP BBS scraping unless Yahoo JP genuinely supports that symbol.

### 7. Add Feedback Memory

If a deep dive says `3350.T -> Pass for now`, the next digest should not promote it again as `[NEW NAME]` unless a new catalyst appears.

Add a decision log:

```json
{
  "ticker": "3350.T",
  "decision": "pass",
  "reason": "No clean value_chain fit; mostly Bitcoin/speculative crowd heat",
  "date": "2026-06-07",
  "suppress_until": "2026-07-07",
  "what_would_change_mind": "New non-crypto catalyst or explicit new crypto value_chain"
}
```

### 8. Improve The Atlas As A Business Object

The atlas is currently mostly a static watchlist. It should become a living research map.

Useful company fields:

- Current thesis
- Latest catalyst
- Valuation concern
- Laggard/leader status
- Last reviewed date
- User decision
- What would change the decision
