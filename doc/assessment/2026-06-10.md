# Business Assessment: Potential Elephant

Date: 2026-06-10

## Executive Assessment

Potential Elephant is useful for top-of-funnel discovery, but it is not yet strong enough for the core business purpose: finding thematic laggards that deserve research before re-rating.

It is already collecting valuable signal. As of 2026-06-10, the local API/data store showed roughly:

- 343k Yahoo Finance Japan BBS comments
- 2,112 Yahoo BBS evaluation snapshots
- 1,290 Minkabu records
- Recent news headlines
- TDnet disclosures
- Daily price records
- A running scheduler

That means the project has a real data foundation. The main business gap is not data collection; it is candidate qualification.

The system should prioritize:

```text
river fit + laggard status + catalyst evidence + sentiment confirmation
```

Today, the digest often prioritizes:

```text
BBS heat + analyst target + vague theme language
```

This is helpful for finding smoke, but not yet disciplined enough to decide whether the smoke is from a real thematic fire or just crowd noise.

## Where The System Helps

The tool already does several useful things:

- It finds crowd heat quickly. BBS rank and comment speed catch active names such as `3350.T`, `5016.T`, `8136.T`, and `6981.T`.
- It uses the right kinds of sources: BBS sentiment, comments, Minkabu consensus, TDnet, news, price context, and a curated river tree.
- Deep dives can reject noise. The `3350.T` deep dive correctly concluded "Pass for now" because Metaplanet is mostly a Bitcoin/speculation story, not a clean fit for the current four rivers.
- The river tree provides a promising structure for comparing companies by theme and supply-chain layer.

## Where The System Falls Short

The daily product still confuses attention with business relevance.

The tool is designed around a strong investment philosophy: find confirmed thematic waves, map the supply chain, then look for structurally relevant companies that have not yet been re-rated by the market. The current digest does not enforce that philosophy strongly enough.

Main issues:

- It does not yet use the river tree as a quantitative map of relative laggards.
- It sometimes promotes tickers with high BBS activity before proving river fit.
- It relies too much on the LLM to judge candidates instead of first creating a deterministic score/ranking.
- It does not consistently explain why a ticker appeared in a reproducible way.
- It does not remember prior "pass" decisions strongly enough.

## Evidence From Data

### 3350.T: Useful Heat Detection, But Poor River Fit

The 2026-06-09 digest surfaced `3350.T` as `[NEW NAME]`. The signal was understandable: price had fallen sharply, comment speed had accelerated, and Minkabu showed bullish analyst context.

But from a business-purpose perspective, this is not a strong river candidate. Metaplanet is mostly a Bitcoin/speculation story, not a clean fit for `ai_infra`, `tech_local`, `physical_ai`, or `longevity`.

The deep dive correctly identified this and concluded `Pass for now`. That means the system can reject noise after a user spends time on a deep dive, but the digest should ideally classify it as "crowd heat/noise" before it consumes attention.

### 5016.T: Potential False Negative

`5016.T` is more interesting. The digest flagged it as a holding signal, and Minkabu identifies JX Advanced Metals as a nonferrous metals and electronic materials company with semiconductor, rare metal, optical-device, and advanced-material themes.

That sounds plausibly relevant to `tech_local` or `ai_infra` middle-layer materials.

However, the existing deep dive said it had no clear river fit and treated it as mostly noise. That may be a false negative. It suggests the system is not yet good enough at mapping materials/specialty suppliers into the river framework.

### 8136.T: Crowd Panic, Not Thematic Signal

`8136.T` had a major comment-speed spike, around `88.26 c/h`, but the live BBS sentiment was strongly negative. This is useful as a "crowd panic" alert, but not necessarily useful for the current thematic supply-chain strategy unless a separate IP/consumer river is intentionally added.

This kind of name should be categorized separately from river candidates.

## Business Verdict

Current usefulness:

- Discovery engine: useful, about 7/10
- Thematic laggard scout: promising but currently about 4/10
- Research assistant after a ticker is chosen: useful, about 6/10
- Decision support for "what deserves my time today?": not reliable enough yet

The tool has the right raw ingredients. The highest-value next step is to become stricter about candidate qualification before the digest is written.

## Recommended Improvements

### 1. Add A Deterministic Candidate Score

For every ticker, compute a pre-LLM score:

```text
river_fit_score
relative_laggard_score
bbs_heat_score
sentiment_quality_score
catalyst_score
noise_penalty
```

Only let the LLM write the final explanation after this ranking exists.

### 2. Split The Digest Into Three Queues

Do not mix different signal types in one undifferentiated digest.

Recommended queues:

```text
A. River Candidates
   Fits a river, underperformed peers, has plausible catalyst.

B. Holding Signals
   Already in tree/watchlist, price down but thesis/sentiment intact.

C. Crowd Heat / Noise
   High BBS activity, but no river fit yet.
```

`3350.T` belongs in C unless a crypto river is intentionally added. `5016.T` may belong in A. `8136.T` belongs in C.

### 3. Make Relative Laggard Detection The Core Screen

The stored price data already enables this. For each river/layer, compute layer median returns and show names that underperform comparable nodes.

Example output:

```text
5016.T
Layer candidate: tech_local / middle
2w return: -11.6%
Layer median: +x%
BBS: bull 62.5%, speed stable
Minkabu: analyst buy, semiconductor/electronic material themes
Risk: recent IPO / valuation / sentiment weakening
Next action: read TDnet + latest company filing
```

### 4. Add Freshness And Reproducibility To Every Hint

Each digest hint should show:

- BBS snapshot time
- Latest comment time
- Latest price date
- Latest Minkabu scrape time
- Source links

The digest should make it possible to answer: "Why did this appear today?"

### 5. Normalize Data Quality Before Trusting Sentiment

Some Yahoo evaluation rows appear to have schema drift where bearish fields are missing or become `NaN`. This can make bull/bear interpretation wrong.

All evaluation records should be normalized to the same five sentiment fields:

```text
strongest
strong
both
weak
weakest
```

Missing values should be coerced to zero or explicitly marked as unavailable.

### 6. Fix Market Routing

Scheduler logs showed attempts such as `STM.T`, `XLU.T`, and `LLY.T` against Yahoo Japan style URLs. That wastes scrape time and may introduce bad data assumptions.

US tickers should use US-compatible sources, or be excluded from Yahoo JP BBS scraping unless Yahoo JP genuinely supports that symbol.

### 7. Add Feedback Memory

If a deep dive says `3350.T -> Pass for now`, the next digest should not promote it again as `[NEW NAME]` unless a new catalyst appears.

Add a decision log:

```json
{
  "ticker": "3350.T",
  "decision": "pass",
  "reason": "No clean river fit; mostly Bitcoin/speculative crowd heat",
  "date": "2026-06-07",
  "suppress_until": "2026-07-07",
  "what_would_change_mind": "New non-crypto catalyst or explicit new crypto river"
}
```

### 8. Improve The River Tree As A Business Object

The river tree is currently mostly a static watchlist. It should become a living research map.

Useful node fields:

- Current thesis
- Latest catalyst
- Valuation concern
- Laggard/leader status
- Last reviewed date
- User decision
- What would change the decision

- [ ] Add a data-quality normalization layer for Yahoo BBS evaluation records so `strongest`, `strong`, `both`, `weak`, and `weakest` always exist with predictable numeric values.
- [ ] Add a market-routing helper that classifies tickers as JP, US, ETF, or unknown and prevents invalid Yahoo JP scrape attempts such as `STM.T`, `XLU.T`, and `LLY.T`.
- [ ] Add a candidate metrics builder that joins ticker rank, comment speed, sentiment, latest comment timestamp, Minkabu availability, TDnet disclosures, and price returns into one structured table.
- [ ] Add river/layer performance calculations using stored `daily_prices`, including layer median return, ticker return, relative laggard gap, and return window.
- [ ] Add a first-pass river-fit classifier for unknown tickers that can run before the digest and produce `fits_existing_river`, `river_id`, `layer`, `confidence`, and `reason`.
- [ ] Implement a deterministic candidate score with fields for `river_fit_score`, `relative_laggard_score`, `bbs_heat_score`, `sentiment_quality_score`, `catalyst_score`, and `noise_penalty`.
- [ ] Refactor digest generation so the LLM receives pre-ranked candidate groups instead of raw top BBS tickers.
- [ ] Split the digest output into `River Candidates`, `Holding Signals`, and `Crowd Heat / Noise`.
- [ ] Add source evidence blocks to every digest hint: BBS URL, Minkabu URL, latest data timestamps, price window, TDnet links when available.
- [ ] Add a decision log persisted under `$DATA_DIR`, recording user/deep-dive decisions such as `watch`, `river_candidate`, and `pass`.
- [ ] Use the decision log to suppress repeated low-value names unless a new catalyst or materially changed score appears.
- [ ] Add river tree node metadata fields for thesis, latest catalyst, laggard/leader status, last reviewed date, user decision, and what would change the decision.
- [ ] Update the deep-dive prompt to explicitly compare suspected suppliers against existing river/layer peers before declaring "no river fit".
- [ ] Add a specific supplier/materials mapping guide for ambiguous names like `5016.T`, where semiconductor/electronic-material relevance may be missed.
- [ ] Add CLI/API endpoints for the candidate metrics table so the frontend can show "why this appeared today" without requiring a generated digest.
- [ ] Add frontend views for the three digest queues and candidate evidence, with sortable columns for rank, river fit, laggard gap, sentiment, catalyst, and freshness.
- [ ] Add basic regression fixtures for known cases: `3350.T` should classify as crowd heat/noise, `8136.T` as crowd heat/panic, and `5016.T` as a possible materials/supplier candidate requiring review.
- [ ] Add freshness checks that warn when sentiment is current but comment text, Minkabu, or price data is stale.
- [ ] Update docs to distinguish "crowd heat" from "river candidate" so future prompts and UI copy preserve the investment philosophy.
